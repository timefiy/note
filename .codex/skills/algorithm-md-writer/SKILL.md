# Algorithm MD Writer

## Overview

根据当前仓库已有题解风格，创建或更新单题 `md` 文档，确保结构统一、中文表达统一、代码与 `cpp` 保持一致。

## Workflow

1. 定位目标题目 `cpp` 与同目录或同标签下的参考 `md`
2. 提取并复用固定结构：frontmatter、标题、题目描述区、核心思路区、代码实现区
3. 按用户要求处理题目描述区：
   - 仅保留图片占位：`![]()`
   - 或保留简要文字 + 图片
4. 从 `cpp` 提取最终可运行实现，放入 `> [!code]` 代码块
5. 全文使用中文，术语与现有文档保持一致
6. 按“题目归档路径规则”将 `cpp` 与 `md` 放置到对应目录
7. 写回目标 `md` 并自检格式

## Output Template

默认输出骨架如下（按需增删）：

```md
---
题号: <number>
tags:
  - <tag1>
  - <tag2>
---

# <题目名>

> [!question] 题目描述
> ![]()

---

> [!light] 核心思路
> **破局点**：<一句话>
>
> 1. <步骤1>
> 2. <步骤2>
> 3. <步骤3>

---

> [!code] 代码实现
>
> ```cpp
> // from target .cpp
> ```
```

## Editing Rules

- 保持与项目既有文档一致的 callout 风格（`[!question]`、`[!light]`、`[!code]`）
- 优先最小改动：用户只要求删某段时，不改其他部分
- 若用户要求“只留图片位置”，删除题目描述正文，仅保留 `![]()`
- 代码块语言固定为 `cpp`
- 非必要不新增“优化”“题解二”等扩展小节
- `tags` 冲突处理顺序（必须执行）：
  1. 若用户显式给出 tag，先接收候选列表；
  2. 对候选列表执行过滤：删除赛事/身份/难度分层类标签（如“第xx场周赛/双周赛”“初级工程师/高级工程师/资深工程师”等）；
  3. 仅保留题型与算法标签（如数组、哈希表、二分查找、动态规划、位运算等）；
  4. 过滤后若为空，再按 LeetCode 题面可确认的题型标签补齐。
- 当用户给出的 tag 与本规则冲突时，优先遵守本规则并自动过滤，不得原样写入被禁用标签。
- 题目归档路径规则（必须执行）：
  1. 每次完成题解后，保证同题 `cpp` 与 `md` 位于同一主题目录；
  2. 同时命中“数据结构标签”和“算法思想标签”时，优先按算法思想目录归档；
  3. 目录优先级：算法思想（如前缀和、差分数组、滑动窗口、二分答案、单调栈、并查集应用思想） > 数据结构（如数组、哈希表、链表、栈、队列、二叉树）；
  4. 仅当无法识别明确算法思想时，才归档到数据结构目录；
  5. 若用户明确指定目录，则遵循用户指定目录。

## Validation Checklist

- frontmatter 字段完整：`题号`、`tags`(如果我说明tag请使用我说明的tag，如果不确定tag请去力扣官网寻找对应的题目并且找寻对应的tag并填上（什么第几周周赛,资深工程师之类的不用填写），如果题目为会员题目找不到请自己填写tag)
- `tags` 最终结果不得包含赛事/身份类标签（如“第xx周赛/双周赛”“高级工程师”等）
- 标题与题号匹配
- 题目描述区符合用户要求（纯占位或含文字）
- 核心思路为中文且步骤编号连续
- 代码与目标 `cpp` 一致，无缺失类型定义依赖说明（如 `ListNode` 由平台提供时可省略）
- `cpp` 与 `md` 已落位到正确主题目录，且两者路径一致（同目录同题名）
