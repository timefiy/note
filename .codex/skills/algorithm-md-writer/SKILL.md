# Algorithm MD Writer

## Overview

根据当前仓库已有题解风格，创建或更新单题 `md` 文档，确保结构统一、中文表达统一、代码与 `cpp` 保持一致。

## Workflow

1. 定位目标题目 `cpp` 与同目录或同标签下的参考 `md`
2. 提取并复用固定结构：frontmatter、标题、题目描述区、核心思路区、代码实现区
3. 按用户要求处理题目描述区：
   - 仅保留图片占位：`![]()`
   - 或保留简要文字 + 图片
4. 从 `cpp` 提取最终可运行实现，放入 `> [!code]` 代码块
5. 全文使用中文，术语与现有文档保持一致
6. 写回目标 `md` 并自检格式

## Output Template

默认输出骨架如下（按需增删）：

```md
---
题号: <number>
tags:
  - <tag1>
  - <tag2>
---

# <题目名>

> [!question] 题目描述
> ![]()

---

> [!light] 核心思路
> **破局点**：<一句话>
>
> 1. <步骤1>
> 2. <步骤2>
> 3. <步骤3>

---

> [!code] 代码实现
>
> ```cpp
> // from target .cpp
> ```
```

## Editing Rules

- 保持与项目既有文档一致的 callout 风格（`[!question]`、`[!light]`、`[!code]`）
- 优先最小改动：用户只要求删某段时，不改其他部分
- 若用户要求“只留图片位置”，删除题目描述正文，仅保留 `![]()`
- 代码块语言固定为 `cpp`
- 非必要不新增“优化”“题解二”等扩展小节

## Validation Checklist

- frontmatter 字段完整：`题号`、`tags`(如果我说明tag请使用我说明的tag，如果不确定tag请去力扣官网寻找对应的题目并且找寻对应的tag并填上（什么第几周周赛之类的不用填写），如果题目为会员题目找不到请自己填写tag)
- 标题与题号匹配
- 题目描述区符合用户要求（纯占位或含文字）
- 核心思路为中文且步骤编号连续
- 代码与目标 `cpp` 一致，无缺失类型定义依赖说明（如 `ListNode` 由平台提供时可省略）
