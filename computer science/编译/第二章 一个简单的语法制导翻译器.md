# 第二章 一个简单的语法制导翻译器
**2.1 引言**

- **分析与综合模型**：编译器前端主要负责分析阶段，根据源语言的“语法”将程序划分并生成中间代码；后端负责合成阶段，将中间代码翻译成目标程序。
- **前端工作流**：源程序经过词法分析器（生成词法单元）、语法分析器（生成语法分析树）、最后由中间代码生成器产生中间表示形式。

**2.2 语法定义**

- **上下文无关文法（CFG）**：用于精确描述程序设计语言的层次化语法结构。它包含四个核心元素：**终结符号**（词法单元，如关键字、符号）、**非终结符号**（语法变量，表示终结符号串的集合）、**产生式**（替换规则）和**开始符号**。
- **推导与语法分析树**：推导是从开始符号出发，不断用产生式体替换非终结符号的过程；语法分析树则是推导过程的图形化展现，其叶子结点从左到右构成了树的“结果”。
- **二义性**：如果一个文法可以为同一个输入串生成两棵或更多不同的语法分析树，则该文法具有二义性，必须通过附加规则消除。
- **结合性与优先级**：用于消除表达式的二义性。左结合运算符（如 `-`）的分析树向左下延伸；不同优先级的运算符通过引入不同层级的非终结符号（如 `expr`、`term`、`factor`）来隔离。

**2.3 语法制导翻译**

- **属性与综合属性**：属性是与程序构造相关的量（如数据类型）。如果在语法分析树结点上的属性值仅仅由其子结点或该结点本身的属性值定义，则称为**综合属性**，可以通过自底向上的树遍历来计算。
- **语法制导定义（SDD）**：一种关联属性和文法符号，并为每个产生式提供语义规则来计算属性值的规范。
- **树的遍历**：定义了属性求值的顺序，通常使用深度优先遍历，包括前序遍历（第一次访问结点时执行动作）和后序遍历（最后离开结点前执行动作）。
- **语法制导的翻译方案（SDT）**：在文法产生式体中显式嵌入程序片段（称为**语义动作**），指明计算或打印操作发生的具体执行顺序。

**2.4 语法分析**

- **自顶向下分析**：从语法分析树的根结点开始，逐步向叶子结点构造，本质是寻找输入串的“最左推导”。
- **预测分析法**：一种不需回溯的递归下降语法分析形式。通过“向前看”（lookahead）输入中的下一个终结符号，结合文法的 FIRST 集合，无二义地确定该调用哪个产生式。
- **消除左递归**：左递归文法（如产生式右部最左符号是头符号本身）会导致自顶向下的分析器进入无限循环，必须通过引入右递归和新非终结符号将其消除。

**2.5 简单表达式的翻译器**

- **抽象语法与具体语法**：抽象语法树（AST）去除了具体语法树中无用的“辅助”符号，每个内部结点直接代表一个运算符，子结点代表运算分量。
- **调整翻译方案**：为了适应自顶向下的预测分析，需要对基础文法消除左递归，并在转换过程中小心保持语义动作的原有执行顺序。
- **翻译器的简化**：在手写编译器前端时，可以通过将无参数过程的尾递归（Tail Recursion）调用替换为迭代（如 `while` 循环），来简化代码并减少函数调用数量。

**2.6 词法分析**

- **职责**：读入源程序字符，过滤掉无意义的空白符和注释，将它们组织成词素，并向语法分析器返回“词法单元对象”（Token）。
- **预读机制**：在确定词素边界前，词法分析器常需要预读一个或多个后续字符（如区分 `<` 和 `<=`），这通常借助于输入缓冲区和指针回退来实现。
- **符号与保留字识别**：使用一个字符串表（如哈希表）保存关键字和已识别的标识符，这既实现了词素的单一高效表示，又解决了关键字作为保留字的判定问题。

**2.7 符号表**

- **功能**：在编译期间保存有关源程序标识符的各种信息（如词素、类型、相对存储地址等），并在声明与使用之间传递这些信息。
- **作用域与最近嵌套规则**：通过为每个语句块或作用域建立一个独立的符号表，并将内层符号表通过指针链接到外层符号表，形成链表或树形结构，从而支持变量的块结构和重新声明。

**2.8 生成中间代码**

- **中间表示形式**：最常见的两种形式是树形结构（如抽象语法树）和线性表示（如三地址代码）。
- **语法树的构造**：在分析过程中创建结点对象（如 `new Node(...)`），运算符作为内部结点，运算分量作为子结点。
- **静态检查**：在中间代码生成时伴随进行的语义检查（如类型检查），以确保运算符和操作数类型匹配，编译器会在此时捕捉语法以外的错误。
- **三地址码转换**：将语法树的复杂层次结构打平，转换成类似汇编的指令序列。每条三地址指令右侧最多有一个运算符，这要求编译器主动生成临时变量（如 `t1`, `t2`）来存放中间计算结果。
